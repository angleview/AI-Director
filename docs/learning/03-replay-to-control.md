# 第三课：把真实模型接入可回放控制流水线

这一层把前两课连起来：视频帧不再由脚本构造，感知结果也不再预先写死；每一帧依次经过 OpenCV 解码、YOLO/NCNN 姿态推理、状态机、构图控制器和虚拟执行器，并留下可审查的 JSONL 记录。

## 适配器边界

`UltralyticsPoseBackend` 是框架世界和项目领域世界的边界。外侧是 `Results`、tensor、像素坐标和 17 个 COCO 关键点；内侧只有 `Perception`、`TargetObservation` 和 `Gesture`。状态机不导入 Ultralytics，控制器不认识 NumPy，因此它们能在没有模型、摄像头或树莓派的电脑上测试。

这也是嵌入式/DSP 移植的共同方法：先定义稳定输入输出，再把平台相关实现封装在适配层。换成其他推理引擎时，核心逻辑不应跟着重写。

## 像素坐标为什么要归一化

原型以固定像素阈值判断位置和手部距离，输入分辨率变化后含义会漂移。新后端把目标中心、框面积和手部距离转换成 `[0, 1]` 比例：

```text
center_x = pixel_x / frame_width
center_y = pixel_y / frame_height
area_ratio = box_width * box_height / (frame_width * frame_height)
```

关键点坐标为 `(0, 0)` 时按不可见处理。单人优先取双眼中心，眼睛不可见则取鼻尖，再不可见才退回检测框中心。多人构图取所有保留目标的中心均值，而不是永远跟随置信度最高的一人。

## 为什么先视频回放

摄像头会带来曝光、抖动、掉帧和时间变化，复现失败时很难区分是模型、业务逻辑还是硬件输入的问题。固定视频让每次运行拥有相同帧序列，适合验证状态转移、控制意图顺序和回归问题。摄像头是后续输入适配器，不是核心逻辑的前提。

## 运行完整链路

```bash
cd .
PYTHONPATH=src python3 -m edge_ai_director.replay \
  --video assets/replays/bus-static-3s.avi \
  --model yolov8n-pose_ncnn_model \
  --output results/replay-640.jsonl \
  --limit 30 --imgsz 640 --conf 0.25 --min-area 0.01
```

JSONL 第一行记录配置，中间每行对应一帧，最后一行是汇总。虚拟执行器只证明控制请求的顺序、限幅和最终逻辑位置，不能表述为真实舵机精度。

1. 为什么推理框架对象不能直接穿透到状态机和控制层？
2. 依赖注入如何让真实后端在没有 NCNN 的电脑上被测试？
3. 关键点缺失时为什么需要分级回退？错误回退会怎样影响控制？
4. 固定视频回放能验证确定性，但为什么仍不能替代摄像头在线测试？
5. 两人构图为什么取群体中心？如果目标短时漏检，画面会发生什么跳变？
