# 第二天上半场：图像、姿态推理、状态机与控制

用时约 4 小时。前置：完成第一天，能够解释函数、类、数据对象和核心调用顺序。学习顺序：图像 → 模型 → 视觉观测 → 状态 → 控制意图。

## 1. 图像在程序中是什么

彩色图像通常是形状为 `(height, width, channels)` 的数组。OpenCV 常见彩色图像是 BGR 三通道，8 位无符号整数，每通道取值 0–255；模型所需颜色顺序、数值范围和布局由其预处理契约决定。

一张 1920×1080、三通道 uint8 图像的像素数据为：

~~~text
1920 × 1080 × 3 = 6,220,800 bytes ≈ 5.93 MiB
~~~

这不含对象和对齐等额外开销。30 次/秒完整复制就是约 178 MiB/s 的数据量估算，尚未计入其他读写；这是估算，不是项目实测带宽。

坐标 x 向右增大，y 向下增大。数组访问通常是 `image[y, x]`，形状先高后宽；OpenCV resize 的尺寸参数通常是 `(width, height)`，这两个顺序容易混淆。

数组切片的示意：

~~~python
crop = image[y1:y2, x1:x2]
~~~

切片可能是原数组的视图；是否复制、是否连续要具体检查。原型明确存在 frame.copy、resize、JPEG 解码与编码，不能把整个链路叫零拷贝。数组基本概念可查 [NumPy quickstart](https://numpy.org/doc/stable/user/quickstart.html)。

### 练习

640×360 图像中位置 (480, 90)，归一化为 `(0.75, 0.25)`。同一位置比例在 1920×1080 中为 (1440, 270)。归一化使控制阈值表达为画面比例。

## 2. 训练、推理、部署的区别

**训练**用数据和损失函数更新权重。**推理**使用既有权重把新图像映射成预测。**部署**让模型与预处理、后处理、设备和业务逻辑在目标环境正确协作。

仓库证据主要是 YOLOv8n Pose 的端侧推理和工程集成，没有独立训练数据集、训练过程与精度评估的完整证据。不能把使用预训练模型说成“自行设计并训练模型”。

神经网络可直观理解为由许多有参数的计算层组成：输入图像经过特征提取，再产生框、分数、关键点等输出。三天先理解输入输出契约，不要求推导反向传播。

### 本项目的视觉输出

YOLO Pose 一次预测可提供人体框和身体关键点；关键点索引用于解释身体部位。当前适配器使用：

| 索引 | 部位 | 代码用途 |
| --- | --- | --- |
| 0 | 鼻子 | 跟随位置回退、举手参照 |
| 1、2 | 左右眼 | 双眼中心、左手参照 |
| 9、10 | 左右手腕 | 举手和展示规则 |

模型输出不是动作命令。适配器再把输出转成 `TargetObservation` 和手势事实。Pose 概念与输出对象可参考 [Ultralytics 官方 Pose 文档](https://docs.ultralytics.com/tasks/pose)；当前文档示例可能使用新模型，项目历史版本是 YOLOv8n Pose / Ultralytics 8.3.x，不要直接照搬最新示例替换历史资产。

## 3. 推理前后都在做什么

~~~text
压缩图片/视频
 → 解码为图像数组
 → 预处理：缩放、布局/颜色/数值调整等
 → 网络计算
 → 后处理：解码输出、过滤、NMS、坐标映射等
 → 框与关键点
 → 本项目的目标选择和几何规则
~~~

项目通过 Ultralytics 包装器完成模型预处理和后处理，并没有在 Python 中从头实现这些步骤。原型先把画面缩成 480×270，并不保证网络实际按该形状计算；包装器还可能按默认 imgsz 再调整。

**等比缩放与补边（letterbox）**：保持原图比例，缩放后在边缘填充，避免直接拉伸人体。映射回原图时需要撤销缩放和补边。核心适配器使用 Results 中映射后的坐标，再除以原帧宽高。

**置信度**：模型的评分，用于筛选；0.9 不应简单宣称为经校准的“90% 正确概率”。

**NMS**：按分数选择候选并抑制高重叠重复框。IoU = 交集面积 / 并集面积。它解释重复候选筛选，但不能据此断言本次 480 异常只由 NMS 引起。

手算 IoU：面积都为 100 的两个框，交集 50，IoU = 50/(100+100−50) = 1/3。知道这个比例如何表示重叠就够开始阅读后处理统计。

## 4. NCNN 的角色与资产

NCNN 是推理框架；YOLO 是模型系列；Ultralytics 是本项目加载和预测的包装接口。Python 调用底层库，不等于 Python 自己逐个算卷积。

| 文件 | 作用 |
| --- | --- |
| `model.ncnn.param` | 网络层、连接和参数描述 |
| `model.ncnn.bin` | 权重数据 |
| `metadata.yaml` | 导出配置和任务等元信息 |
| `model_ncnn.py` | 仓库中的生成辅助代码，不替代 bin 权重 |

文件格式可查 [NCNN 官方说明](https://github.com/Tencent/ncnn/wiki/param-and-model-file-structure)。部署集成参考 [Ultralytics NCNN 文档](https://docs.ultralytics.com/integrations/ncnn)。

当前本地缺 bin；历史 Pi 具有完整资产。没有权重不能靠 param 单独恢复原模型。

metadata 中有 `half: true`，可以陈述导出元信息含半精度设置。它不能独立证明每层实际使用 FP16 计算，更不能证明做过 INT8 量化。CPU 支持 FP16/NEON 也不等于已经测量到对应加速收益。

**可复现部署的检查顺序：**解释器与架构 → 依赖版本 → 模型文件完整性及哈希 → 输入契约 → 单张结果 → 性能。原始导出的完整命令尚缺证据，不要补写成自己实际做过的完整转换流程。

## 5. 逐段读 ultralytics_backend.py

### 5.1 初始化和预测

`UltralyticsPoseBackend` 可接受模型路径，或注入 model 对象。没有注入时，延后导入 YOLO，并以 pose 任务加载路径。

`infer(frame)`：

1. 要求 payload 不为空。
2. 调用 predict，显式传入 imgsz 和 confidence。
3. 读取第一个 Results 对象。
4. 提取框、关键点和置信度。
5. 过滤过小目标，按框面积比例降序，最多保留两个。
6. 从第一个选中目标计算手势，返回带原始帧号的 Perception。

默认 `confidence=0.50, imgsz=640, min_area_ratio=0.03, max_targets=2`。保存的 Pi 回放采用 conf 0.25、min-area 0.01；讲实验时要说实验配置，不能只背代码默认值。

### 5.2 面积筛选与位置选取

框格式 xywh 是中心 x、中心 y、框宽、框高。面积比例：

~~~text
area_ratio = box_width × box_height / (frame_width × frame_height)
~~~

例如 640×360 图像中的 160×180 框：比例 = 28800/230400 = 0.125。

大框优先是简单启发式，可能更偏向近处的人。它没有跨帧身份关联，人物交叉、遮挡或大小排序变化都可能切换目标。

`_tracking_point` 优先使用双眼中点，其次鼻子，最后框中心；TargetObservation.center_x/center_y 因而可能是脸部参考位置，不能一概叫人体框中心。

可见性只检查坐标大于零，没有明确使用 keypoint.conf。框置信度高不保证每个手腕都可靠，这会影响手势判断。

### 5.3 手势是几何规则

坐标 y 小意味着位置高：

- 双手手腕 y 都小于鼻子 y：BOTH_HANDS_UP。
- 否则左手手腕 y 小于左眼 y：LEFT_HAND_UP。
- 其余：NONE。
- 双手位于鼻子下方且归一化间距较小：showcase_pose=True。

归一化距离使用 `hypot(dx/width, dy/height)`，不是简单的像素欧氏距离除以宽；横纵方向分别按画面尺寸归一化。默认展示距离阈值 0.125。

举例：鼻子 y=180，两只手腕 y=80，判断双手举起；鼻子 y=180，手腕 y=280，不能判断举起。项目使用姿态模型加规则，没有单独训练“手势分类网络”。

## 6. 状态机：把连续观测变成行为

状态机由当前状态、输入和迁移规则组成。状态代表“系统在做什么”；手势代表“当前看到了什么”；不能把二者混为一个布尔值。

本项目模式：

| 模式 | 含义 | 控制器默认行为 |
| --- | --- | --- |
| SEARCHING | 搜索阶段 | HOLD |
| TRACKING | 按位置构图 | 有目标时计算增量 |
| SHOWCASE | 展示构图规则 | 有目标时计算增量 |
| LOCKED | 锁定构图动作 | HOLD |
| PRIVACY | 无人超时模式 | HOLD |

SEARCHING 这个名字不意味着新核心已实现扫描巡航；PRIVACY 不意味着新核心已实现关摄像头或遮挡画面。这里模式值和物理动作要分开。

### 6.1 手势边沿为什么必要

如果每帧“看到左手举起”都切换锁定，连续三帧会锁定→解锁→锁定。业务需要一次举手产生一次事件。

~~~text
观测：NONE  LEFT  LEFT  NONE  LEFT
事件：NONE  LEFT  NONE  NONE  LEFT
~~~

源码规则是：当前手势非 NONE，且与上一手势不同，才产生事件。所以 LEFT→BOTH 也产生新事件，而不必先回到 NONE；它是“手势类型变化事件”，不能只说成严格的布尔上升沿。

它避免稳定手势重复触发，却不能充分过滤噪声：LEFT→NONE→LEFT 可能因为误检再次触发。完善时可以增加持续时间、连续帧、关键点置信度、冷却时间或迟滞；这些尚未完整实现。

### 6.2 按源码顺序理解迁移

1. 有目标时更新最近目标时间；SEARCHING/PRIVACY 转 TRACKING。
2. 计算手势事件：左手在 LOCKED 与 TRACKING 之间切换；双手只请求复位。
3. TRACKING 中展示姿态持续约 2 秒才进 SHOWCASE；释放或失去目标会退出。
4. 非 LOCKED/SHOWCASE 且无目标时，失踪约 5 秒进 SEARCHING，约 30 秒进 PRIVACY。
5. 保存本次手势，返回 Decision。

进入 SHOWCASE 使用注入的处理时钟 now_ns。离线视频文件即使标注 10 fps，也不意味着状态机每帧自动按 0.1 秒推进；当前回放没有按媒体时间强制实时播放。必须区分文件帧率、处理时间和状态机时间。

左手锁定时，即使无目标，超时逻辑也不会直接把 LOCKED 改为 PRIVACY。这是现有代码行为；要改变产品规则，应先确定需求，不能靠推测解释。

## 7. 控制器：从误差到角度

源文件 `control.py`。核心是 P 控制、死区和单次增量限幅，没有 I 项、D 项或 dt。

1. RESET 优先于其他动作。
2. 只在 TRACKING/SHOWCASE 且有目标时计算。
3. 多个目标的观测位置取算术平均，不是加权中心或跟踪预测。
4. 水平目标为 0.5；单人垂直目标为 0.33，多人或展示为 0.50。
5. 在死区内误差置零。
6. 乘比例增益，按安装方向翻转符号，限制每次增量。

公式及默认值：

~~~text
ex = 0.5 − mean(center_x)
ey = desired_y − mean(center_y)
|ex| < 0.03 时 ex = 0
|ey| < 0.04 时 ey = 0
pan_raw = ex × 18
tilt_raw = −ey × 12
默认 invert_pan=True，因此 pan 翻转
两个轴分别限制到 [−4°, +4°]
~~~

### 完整手算

单人观测 (0.8, 0.6)，TRACKING：

~~~text
ex = 0.5 − 0.8 = −0.3
ey = 0.33 − 0.6 = −0.27
pan_raw = −5.4°，方向翻转后 +5.4°，限幅后 +4°
tilt_raw = +3.24°，未翻转、未触限 → +3.24°
~~~

虚拟执行器初始 (pan=0°, tilt=−90°)，应用后 (4°, −86.76°)。符号由坐标系和安装方向决定，不能只凭“人在右边”断言真实舵机必向某方向转。

第二例：观测 (0.51, 0.34)，误差 −0.01、−0.01，都在死区，HOLD。边界严格使用小于：误差恰好 0.03 不一定被归零，另需注意浮点表示。

### 为什么这样控制

死区减小检测噪声引发的微小动作；增益越大响应越强，但延迟和机械因素可能导致过冲。单步限幅防止一次意图过大，但每帧 4° 不是每秒 4°，频率变化会改变单位时间运动需求。

原型还有 EMA：

~~~text
smoothed = (1−alpha) × previous + alpha × desired
alpha = 0.25
~~~

它让变化平滑，也引入滞后；EMA 不是 PID 的积分项。新核心没有原型的 EMA，介绍时说明自己讨论的是哪份实现。

完整 PID 需要 P 比例误差、I 随时间积分、D 随时间变化率，并处理饱和和抗积分累积等问题。不能仅凭注释或类名把本项目叫完整 PID。

## 8. 虚拟执行器与物理控制的界线

`VirtualActuator`：

- HOLD 保持内存位置。
- RELATIVE_MOVE 在现有位置上加增量。
- RESET 恢复设定复位位置。
- 绝对角度裁剪到各轴安全范围，记录 requested/applied/clipped 和帧号。

控制器限制“单次增量”，执行器限制“绝对位置”，是两道不同约束。虚拟执行器没有真实舵机位置传感器，不测机械误差、延迟、回差或稳定性。当前也不独立强制拒绝倒序帧号，顺序主要由同步调用保证。

原型的 ServoKit angle 调用是通过驱动库给设备发指令；写入成功也不证明舵机到达。实现机械反馈需要额外测量或反馈传感器。
